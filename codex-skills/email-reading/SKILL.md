# Email Reading

Use the connected Gmail tools to read the relevant message or thread before classifying it. Search and read enough context to identify what the message asks, who owes the next action, and any date or deadline. Do not classify from a subject line or Gmail's `IMPORTANT` label alone.

The user's Gmail workflow labels already exist; use their exact names:

- `[To Read]`: worthwhile, nonurgent reading such as a newsletter or article the user wants to revisit. Unwanted subscriptions do not belong here.
- `[Awaiting Response]`: the user has already sent a request or completed their part, and someone else now owes a response or result. Check the thread before assigning this label.
- `[Follow Up]`: the user needs to take a future action, make a decision, pay, submit, or reply. Capture the concrete next action and any real deadline in the summary. If task tracking is part of the request, update or create the matching task without duplicating it.
- No workflow label: completed, irrelevant, or low-value informational mail, including routine terms-and-conditions updates with no required action. Archive it. Check for actual deadlines, required consent, or account changes before deciding it is low value.

Assign at most one of these three workflow labels to a message. Remove an obsolete workflow label when moving it to another state. After recording any useful facts in the relevant note or task, apply the label to the message and archive its thread so it leaves the Inbox. Archive no-label messages too. Do not Trash, unsubscribe, send, or create broad filters unless the user requests that action.

When a message's obligation is genuinely unclear, keep it in `[Follow Up]` with the uncertainty stated; do not silently discard it as informational. Verify the label and archive results, and report any messages that could not be processed. Summarize the triage briefly by category and call out the next deadlines.

## Expert Blind-Spot Check

When the messages concern a consequential decision, deadline, application, contract, or ambiguous obligation, end the user-facing response with a brief **What an expert would flag** section. Surface one to three material implications the user did not ask about, especially dependencies across separate messages, misleading automated wording, missing confirmations, or a premise that should be challenged. Skip it for routine inbox cleanup when no additional issue would change the user's action.
